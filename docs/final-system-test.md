# Final System Test — LaundryTrack (PR #9)

เอกสารนี้เป็นแผนตรวจสอบการทำงานหลักก่อนส่งโปรเจกต์ **ไม่ใช่การรับรองว่าเว็บไซต์จริงผ่านทุกกรณีแล้ว** ผู้ใช้งานจริงยังต้องยืนยันขั้นตอนรับผ้า/ส่งมอบที่ร้าน

## 1. อัตโนมัติบน GitHub Actions (ไม่แตะ Angsila)

Workflow: `.github/workflows/final-system-smoke.yml` สร้างฐานข้อมูล MySQL แยกชื่อ `laundrytrack_ci` รัน PHP web server เฉพาะ `127.0.0.1:18081` แล้วใช้ Python standard library ทดสอบ HTTP จริง ไม่เรียกเว็บไซต์ Angsila

ทดสอบใน `tests/final-system-smoke.py`:
- หน้าหลักและการบล็อกผู้ใช้ที่ยังไม่ล็อกอิน
- POST CSRF token ผิดต้องถูกปฏิเสธ
- Guest สั่งบริการแล้วได้ `requested`, เก็บรายการบริการ, มี QR token
- QR แสดงสถานะโดยไม่เปิดเผยชื่อ/โทรศัพท์ และ feed ต้องมีสิทธิ์ Session
- Admin ล็อกอินสำเร็จ, ห้ามข้ามขั้นตอน, `requested→received` ต้องระบุ `dropoff_confirmed=yes`
- Admin ทำ `received→washing→drying→ready`, บันทึกประวัติ, และไม่สามารถยืนยัน `picked_up` แทนลูกค้า
- Guest ยืนยัน `ready→picked_up`, เฉพาะ Session ที่กดยืนยันรับผ้าเท่านั้นที่เชื่อมบัญชีได้
- หลัง Guest สมัครสมาชิกสำเร็จ QR เก่าถูกยกเลิกทันที
- สมาชิกใหม่สมัคร/ล็อกอิน/สร้างออร์เดอร์/ดูความคืบหน้าได้
- สมาชิกคนอื่นไม่สามารถเปิดออร์เดอร์หรือยืนยันรับผ้าแทนเจ้าของ
- สมาชิกไม่สามารถเรียก Admin API, Admin ไม่สามารถอ่าน Member-only notification feed
- ลูกค้ายืนยันรับผ้าซ้ำแล้วไม่สร้างประวัติซ้ำ

**หมายเหตุ:** อัตโนมัติทดสอบ HTTP และฐานข้อมูล ไม่ใช่การทดสอบ Javascript แบบ browser จริง, การสแกนด้วยกล้องมือถือ, การพิมพ์ QR จริง, การทดสอบ concurrent request หรือการส่งผ้าจริง

CI guard ป้องกันรันผิดที่: `APP_ENV=ci`, `DB_NAME=laundrytrack_ci`, `LAUNDRY_SMOKE_LOCAL_ONLY=yes` และตรวจ `SELECT DATABASE()` อีกชั้น ห้ามนำชุด SQL `tests/fixtures/final-system-base.sql` หรือสคริปต์ทดสอบไปรันบนฐานข้อมูลจริงของมหาวิทยาลัย

## 3. ข้อจำกัด/ความเสี่ยงก่อนเปิดใช้จริง

- **การยืนยันรับผ้าผ่านลิงก์ QR เป็น bearer token**: เจ้าของลิงก์สามารถกดยืนยัน `picked_up` ผ่านหน้าเว็บได้ จึงต้องมีกระบวนการตรวจตัวตน/ส่งมอบผ้าโดยพนักงานก่อนเชื่อสถานะว่าได้รับจริง
- Rate Limiting จำกัดตาม IP สำหรับ Guest — ผู้ใช้หลายคนที่ใช้ NAT ร่วมกันอาจถูกจำกัดร่วม; ป้องกันการโจมตีจากหลาย IP ได้ไม่ครบ
- ระบบสมัครสมาชิกปัจจุบัน **ไม่มีการยืนยันอีเมล** ตามข้อกำหนดล่าสุดที่เลือกข้าม PR #8; ควรระบุข้อจำกัดในเอกสารการส่งงาน
- Dashboard แสดงยอด **ค่าบริการประมาณการ ไม่ใช่รายได้ที่รับชำระแล้ว** อย่ารายงานเป็นยอดเงินเข้าจริง
- การแจ้งเตือนอัปเดตเมื่อเปิดหน้าเว็บไว้ ไม่ใช่ push notification ออกนอกเว็บ
